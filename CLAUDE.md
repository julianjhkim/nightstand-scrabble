# CLAUDE.md

Read README.md first. It covers what the game is, how it is built, how the two
phones stay in sync, and the house rules.

## Workflow

- Edit only `src/template.html`. `dist/index.html` is generated by `build.py`;
  never hand-edit it.
- After any change, run `python3 build.py && npm test`. Both must pass before
  showing the user anything.
- Deploying (Netlify) costs 15 credits out of 300 free per month. Batch changes
  and deploy only when the user asks.

## How to work with the user

- Talk before writing code: say what you found, what the options are, and which
  one you would pick. Wait for "go".
- Don't hand over a built file until asked.
- When something breaks, find the cause instead of patching the symptom. Bugs
  here have looked like one-offs and turned out to be structural:
  - The dictionary judged each word form separately, so HURLED was playable
    while HURL was not.
  - Two phones did read-modify-write on the same key, so each wiped the other's
    name.
- Push back when the user is wrong. Say it plainly.

## The game

- Two players only, Junghyun and Hailey, hardcoded (`PEOPLE` in
  `src/template.html`). The name is the seat: Junghyun is always player 1,
  Hailey always player 2.
- Release notes live in the `NOTES` array in `src/template.html`. The user
  gives the date (format `YYYY.MM.DD`, e.g. `2026.11.01`); add the newest entry
  at the top. Hailey reads these, so write plain English saying what changed and
  why it was wrong before. No jargon, no em dashes.
- All UI text is English (`LANG='en'`). No em dashes in UI text either.
- The dictionary was built from WordNet, Wordset, kengdic and wordfreq, but
  those build scripts are gone. `data/dictionary.json` is the only copy.
  Widening the word list means rebuilding that pipeline from scratch, so tell
  the user before starting any change to the word list.
